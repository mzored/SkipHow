Which layer fits the job you actually have?

SkipHow is not a universal upgrade. Choose it when the missing piece is a stable decision boundary between a product owner and a strong coding agent.

01 · Mechanism

Four products for four different control needs.

Question Base agent SkipHow Spec / workflow framework Runtime orchestrator
Primary job General coding work Outcome-to-verified-result ownership contract Reviewable, staged development method Operate persistent agents and shared resources
Human role Defined per prompt and host defaults Own product outcome, tradeoffs, and protected actions Inspect or approve specs, stages, tickets, or plans Configure teams, policy, budgets, and governance
Agent role Whatever the current prompt establishes Own technical decisions, implementation, procedures, and proof Execute within an explicit method and its artifacts Work inside a managed runtime and coordination model
Persistent machinery Host and repository only None beyond the host and project Usually specs, plans, commands, or state files Server, database, scheduler, leases, or control plane
Best signal The base agent already behaves as needed You want to stay at product-outcome level You want the method visible and reviewable You need durable multi-agent operations
Do not choose it for A boundary the default behavior does not hold Budgets, leases, deterministic phases, or added intelligence A process-free owner experience A thin instruction contract

02 · Selection cases

Start from the sentence you would say.

Use SkipHow

"The checkout hangs after payment. Fix it without changing providers."

You supplied the product result and a boundary. You want the agent to diagnose, choose the technical method, follow project rules, and prove the fix.

Use the base agent

"Add this settled validation and run the existing test."

If your agent already respects scope, does not offload technical decisions, and verifies the result, an extra contract may not improve the outcome.

Use a workflow framework

"Draft a specification for the team to approve before implementation."

The reviewable method is part of the desired product. Explicit artifacts and approval stages are a feature, not overhead.

Use a runtime orchestrator

"Keep twenty agents running under budgets and durable leases."

This needs persistent execution and coordination machinery. Instructions alone cannot provide scheduling, isolation, leases, or budget enforcement.

03 · Claim boundary

A position, not a leaderboard.

No controlled product benchmark has compared SkipHow with a base agent, spec framework, workflow framework, or runtime orchestrator. This page distinguishes mechanisms and user scenarios; it does not claim lower cost, higher speed, better reliability, or better engineering.

SkipHow's useful question is narrower: do you need a portable contract that keeps product decisions with the owner and engineering decisions with the agent?
