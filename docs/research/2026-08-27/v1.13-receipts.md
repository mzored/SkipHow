# 1.13 receipts: five parallel external reviews of the standing package

Date: 2026-08-27. Host: Codex CLI 0.149.1, effective model disclosed as `gpt-5.6-sol`.
Reviewed candidate: `main` at 1.12.0 (`62970ba`), the whole package rather than a diff.

This is the first use of the 1.12 cross-host rung against SkipHow itself as a standing
artifact. 1.12 reviewed its own diff five times in series; this round reviewed five
different constituents of the project at once. Both are the same rung: the reviewer runs
on the other installed host, at `high` effort, with no model named.

## What was run

Five `codex exec` passes launched together, each read-only, each given the same preamble
(what the package is, which alternatives the ADRs have already rejected, the word budgets,
and the receipt rule) plus one scope:

| Lane | Scope | Findings returned |
| --- | --- | --- |
| A | `SKILL.md` and all eight references, read as one contract | 7 P1, 4 P2 |
| B | agent adapters, `openai.yaml`, `hooks.json`, both manifests, host CLI flags | 2 P1, 6 clean |
| C | `scripts/check.py`, `check_hosts.py`, `run_summary.py` as ordinary programs | 10 P1, 4 P2, 1 P3 |
| D | both test files against the things they assert on | 8 P1, 2 P2, 1 P3 |
| E | every document against what the package actually contains | 0 P1, 7 P2, 2 P3 |

`codex exec` was used rather than `codex review` because the working tree was clean: there
was no candidate diff to scope to. The scope flags remain mutually exclusive with a prompt
([1.12 receipts](v1.12-receipts.md)), so the brief carried the scope either way.

Parallel lanes are the reason the count is this high, and they are not free: the same
defect can surface in two lanes with different framings, and a lane given a narrow scope
reports inside it rather than saying the problem belongs elsewhere. Both happened here.

## What was confirmed independently before any fix

- **Subagent worktrees do not branch from the session HEAD.** Lane B asserted this from
  the current documentation; it was checked against the primary source rather than
  accepted. `code.claude.com/docs/en/sub-agents`: `isolation: worktree` gives "an isolated
  copy of the repository branched by default from your default branch rather than the
  parent session's `HEAD`". `code.claude.com/docs/en/worktrees` adds that subagent
  worktrees follow `worktree.baseRef`, whose default `"fresh"` branches from
  `origin/HEAD`, and that `"head"` is the setting for "isolating subagents that need to
  operate on in-progress work". SkipHow delegates a unit while the run sits on a feature
  branch, so this is a real defect in the shipped `builder` adapter and not a doc nit.
- **The model-ID scan named no current Claude family.** Run directly against the compiled
  pattern: `claude-fable-5` and `fable-5` returned no match, and so did `gpt-oss-120b`,
  `grok-4`, `deepseek-v3` and `qwen3-235b`. `claude-opus-5`, `o3` and `gemini-2.5-pro`
  matched.
- **The personal-path scan required a trailing separator.** A macOS home path matched when
  it continued past the user name and did not match when it ended there — the ordinary
  spelling in a sentence. Its Windows branch carried no `IGNORECASE`, so the same path with
  a lower-case drive component slipped through as well.
- **Each new guard was planted against.** An extra `agents/extra.txt`, a `claude-fable-5`
  in `openai.yaml`, a home path ending at the user name in a reference, and a hook whose
  command opened a network connection with a program the denylist never named, were each
  introduced in turn;
  each is now rejected by name, and each file was restored.
- **Each strengthened test was mutated against.** Swapping the two cross-host commands so
  each host reviews itself, adding `id-token: write` under `permissions`, adding an
  unpinned job-level `uses:`, renaming the builder's tools to `EditHistory, WriteSummary`,
  and raising the root budget tenfold each left the suite green before and fail after.
- **Every published number was recounted.** The paired-evaluation table gives $0.29 to
  $0.42, $0.51 to $0.57 and $0.51 to $0.65, which is 45, 12 and 27 percent, not the
  "20 to 30 percent" both README and the receipt's own Reading section carried.

## What was rejected, and why

- **`github.md` grants Issue and pull-request creation without an exact owner grant**
  (lane A). The root routes tracked delivery through a repository rule that "requires an
  Issue-linked branch or pull request", which is a gate the reference satisfies, not a
  widening it invents. Dismissed.
- **Deleting `.skiphow/handoff.md` needs the root's cleanup grant** (lane A). The handoff
  is the run's own bookkeeping, created and disposed of by the same reference; the root
  reserves irreversible deletion of project and owner data.
- **The hook should resolve the repository root** (lane B). Real, and marginal: a session
  started in a subdirectory writes and reads `.skiphow/` in that same subdirectory, so the
  hook and the skill agree. Both proposed fixes are unavailable — `git rev-parse` and
  `$(` are rejected by the hook validator on purpose, and `${CLAUDE_PROJECT_DIR}` is the
  directory the session started in, which is the subdirectory. Recorded, not fixed.
- **The release workflow skips the version-bump gate** (lane C). It does, and the gate
  fires on the pull request and on the push to `main` before the tag exists; the release
  job additionally asserts the tag equals `VERSION`. Not a hole.
- **`base...HEAD` ignores uncommitted changes** (lane C). True, and demanding a version
  bump for a dirty working tree would fail every mid-change local run.
- **The root's "list each finding with its tag" cannot cover a fixed finding** (lane A).
  The sentence before it exempts a fixed problem: "Every *other* finding you mention gets
  one tag."

## The candidate's own round

The 1.13 candidate was then sent through the same rung: two lanes at once, one over the
whole diff, one over the rewritten checks and tests. They returned twelve findings, eleven
distinct once the URL false positive both lanes raised is counted once, and all eleven were
acted on. Two were regressions this candidate had introduced while fixing something else,
which is the reason the round was run:

- The hook shape excluded `"`, `$`, backtick and backslash from the message but not `'`.
  A single quote closes the outer `sh -c '...'`, so a message could end the quoting and run
  a program the denylist never names, while still matching the shape. Reproduced against
  the compiled pattern, fixed, and now a regression case.
- Making the trailing separator optional and accepting lowercase reached into `/users/`
  routes inside documented URLs. The portability gate scans public documentation, so that
  would have blocked a release on an innocent link. The POSIX names are canonical again and
  the pattern no longer fires where a host name precedes it; Windows stays case-insensitive,
  because Windows is.

The rest were defects in the fixes themselves: the builder guard checked that the brief's
files were present when the defect is that their contents are stale; `UNSAVED` as "nothing
recorded it" also described a `DISMISSED` finding; `isinstance(False, int)` is `True`, so a
boolean metric still rendered as zero; rejecting a second `result` event broke a valid
streaming-input transcript, which emits one per turn; the reference gained a fifth reason to
stop while README and how-it-works still said four; and three of the new tests compared the
package against the allowlist rather than running the check, so they passed by construction
and would have passed with the check deleted.

A third defect surfaced only by running the check rather than reading it. Narrowing the
managed-policy match to "allowed source" dropped the message this machine actually prints --
"marketplace source `...` is not allowed by requirements from /etc/codex/requirements.toml" --
which turned a legitimate `UNVERIFIED` into a release-blocking `FAIL`. The match now requires
the denial language and the policy reference together, and the observed message is the test's
first case. `python scripts/check_hosts.py` exits 0 again: Claude package validation PASS,
Claude isolated install PASS, Codex validation and Codex isolated install `UNVERIFIED`.

## A third pass, and where it stopped

A third review of the committed candidate returned seven findings; five were acted on. The
builder guard compared the base commit but not its contents, so a parent holding uncommitted
work on a brief-owned file still handed a builder a stale input at the same commit; the model
pattern enumerated families, so `claude-future-5` and `gemini-pro-3` passed exactly as
`claude-fable-5` had, and it now matches a provider name followed by a version whatever the
family words are; the narrowed policy match accepted an unrelated refusal sitting beside a
parse error; `float("nan")` is an instance of `float`, so `NaN` and a negative turn count
were accepted as metrics; and two counts in the changelog did not match the diff.

Two were rejected. A capitalised home-directory name used as a web route in prose still
matches the path scan: tightening further trades a visible, cheap false positive for a silent
leak of the thing the gate exists to catch, and that is the wrong side to err on. The other
was a restatement of the first pass's builder finding.

Each round found fewer, and the third found nothing in the prose contract. The loop stopped
there rather than at zero, because a fourth pass that reviews the text the third pass added
is auditing its own commentary -- the regress 1.12 already recorded.

## What stays UNVERIFIED

- That an owner-facing run reaches the cross-host rung on its own. Unchanged from 1.12; no
  receipt shows a session escalating there by itself. This round drove the passes by hand,
  as `AGENTS.md` requires in this repository.
- The Codex to Claude direction from inside a real Codex session.
- Whether an installed SkipHow plugin in the reviewed repository derails the external
  reviewer. This round again ran where SkipHow governs nothing.
- Whether an in-host same-model reviewer would have found the same set. Not measured, and
  not claimed. No cost or speed claim is made for the parallel shape.
- Codex package validation and Codex isolated install remain `UNVERIFIED` on this machine:
  its managed policy rejects the local marketplace. CI runs the pinned Codex validator.
