## Findings outside the request

The 1.3 pass saved the planted shipping-rate mismatch in 4 of 6 runs that met it. This pass went observed failure, one-line change, rerun, four times:

1. Rule reworded so every finding gets a disposition (tracked, saved, or dismissed with a reason). Small bug run: the finding was named "for you to decide on rather than saving unprompted". The transcript showed the cause: the authority rule says "save" is a grant, so the model treated saving as ungranted.
2. Authority sentence gained "saving a finding you met along the way is always within authority". Retry-feature run (started before this edit): dismissed the finding with the reason "unrelated to this request".
3. Dismissal clause gained "being outside the request is not such a reason". FREESHIP feature run: both findings saved to `.skiphow/inbox.md`, but as loose bullets, because `intake.md` never loads on the delivery route. Rerun after pointing the rule at the intake format: one finding saved as a proper block, the other named under Limits as "pre-existing and not touched".
4. The report rule now asks for each finding under "Rulings and findings" with a tag, `TRACKED`, `SAVED`, or `DISMISSED`, and its reason. Two FREESHIP runs: 2 of 2 findings `SAVED` as intake blocks in each, run artifacts `DISMISSED` with a reason, 7 and 8 turns, $0.60 and $0.62.

Four small-bug and retry runs on the same candidate never opened `shipping.py` and so never met the finding; they reported nothing false. The structural tag was the change that held; prose about materiality was not.

## Epic decomposition

Two requests on the throwaway GitHub repository, "finish end to end, merge what passes":

- Inventory tracking (stock levels, rejection on insufficient stock, restock, low-stock report): one Issue (#14), one PR (#15) merged on the read head, branch deleted, 48 passed. 13 turns, $1.28. The root judged it one bounded change and did not split or delegate.
- Version 2 (a CLI with four subcommands, JSON persistence, CSV import and export): three Issues (#16, #17, #18) with markers, three branches and PRs (#19, #20, #21) squash-merged in dependency order (store, CSV, then the CLI that uses both), handoff written per item and removed at the end, 81 passed on merged `main`, no open PRs, no leftover branches. 15 turns, 235 s, $2.11. Rulings included adding a `catalog` subcommand so the CSV feature was reachable from the CLI. It did not delegate: the three pieces were dependent, so parallel builders would not have saved time.

Decomposition is verified when the pieces are independent enough to track separately, and not forced when they are not. Delegation inside an epic on Claude Code is still unobserved on this fixture; the 1.2 receipt covers `builder` delegation when the owner asks for parallel work.

## Codex delegation with role files

The three `codex-agents/*.toml` files were copied into the fixture's `.codex/agents/`. Request: two independent items "in parallel with subagents, then integrate both with their tests and commit".

The root read `model-routing.md`, called `spawn_agent(agent_type="builder")` twice (the session logs show two subagent threads with `agent_role: builder`), each builder proved its test failed before the fix, the root waited on both, checked the combined diff for overlap, ran the integrated suite (10 passed), and then hit a host limit: the `workspace-write` sandbox refused `.git/index.lock`, so the commit failed. It stopped after one attempt and reported the exact commands under Limits. 327k input tokens (271k cached), 4.6k output.

Named-role spawning on Codex is verified. Per-role effort is not: only `builder` (no effort set, inherits) was spawned; `scout` at `low` and `reviewer` at `high` remain `UNVERIFIED`. Committing from `codex exec` needs a sandbox that can write `.git`; the guide says so.

## What it got wrong

- Three findings edits were needed before the behavior held; each intermediate wording was reasonable and each failed in a different way. Prose that asks for judgment ("when material") is weaker than a required tag.
- One inbox block carried a placeholder timestamp (`00:00:00Z`).
- Retry policy varies between runs (a 4xx allowlist in one, retry-everything in another); both were stated as rulings.

## Not covered

Codex `scout` and `reviewer` effort resolution, delegation inside a Claude Code epic, auto-compaction under a large context, and the Codex isolated install on this machine.
