# 1.1 receipts

Real runs of the 1.1.0 candidate on a throwaway repository, recorded per [ADR 0008](../../decisions/0008-receipts-over-a-live-harness.md). Host: Claude Code 2.1.246, root model `claude-fable-5`, candidate loaded with `--plugin-dir plugins/skiphow` (the installed 1.0.1 plugin disabled), `--permission-mode bypassPermissions`, `--max-budget-usd` per run, `--output-format stream-json` captured for inspection. Codex: `UNVERIFIED` for every scenario below; the package validates and the isolated install is blocked by this machine's managed `requirements.toml`, as in 1.0.

The fixture is a five-file Python "lab shop": `pricing.py` with a percent-as-fraction discount bug, `shipping.py` with a hard-coded rate table that contradicts `config/rates.json` (the planted out-of-scope finding), two passing tests, a README.

## Model routing

Request: an independent read-only review of shipping-rate consistency, delegating inventory to `scout` and the verdict to `reviewer`.

- The root invoked `skiphow:skiphow`, read `references/model-routing.md`, then called `Agent(subagent_type="skiphow:scout")` and `Agent(subagent_type="skiphow:reviewer")`.
- Effective models from the transcript: root `claude-fable-5`, scout `claude-haiku-4-5-20251001`, reviewer `claude-opus-5`. The report named both.
- Scout used only `Read`; reviewer used `Read` and `Bash` (ran pytest, grep, a cwd check). No file changes; the reviewer left a `__pycache__/` and the root named it under Limits instead of deleting it.
- Report used the five headings. Verdict: inconsistent, owner decision needed on 5.0 vs 6.0. Correct.
- 7 turns, 79 s, $0.65.

Routing on Claude Code is verified. Codex routing `UNVERIFIED`.

## Handoff and resume

Request: a three-item queue end to end, with an instruction to pause after item 1 and leave a handoff.

Session 1: invoked the skill, read `delivery.md` and `long-work.md`, fixed the discount bug with two regression tests, committed (`fdad1c8`), wrote `.skiphow/handoff.md` in exactly the eight-line format, committed it, and stopped with a five-heading report that also named the 5.0 vs 6.0 finding for the next session. 7 turns, $0.55.

Session 2: `claude -p "Continue the queue to the end." --resume <session>`. The `SessionStart:resume` hook fired (`hook_started` and `hook_response` events in the stream) and its output was the reminder sentence followed by the checkpoint. The session ran `git status` and `git log` first, did not touch item 1, completed items 2 and 3 with tests (`369e545`, `120f4fc`), updated the handoff to "queue complete", and reported under the five headings with the 5.0 to 6.0 behavior change listed as a ruling. 4 turns, $0.57. Resume continuity is verified on Claude Code.

## Small task

Request: "Customers who get a 10 percent discount see a negative order total. Find the cause and fix it." No mention of SkipHow.

Run 1 (original skill description): the skill was not invoked. The host fixed the bug correctly in 4 turns ($0.48) with regression tests, no branch or Issue, and mentioned the shipping finding in passing. Correct outcome, but the policy did not load, so the report format and the "save once" rule did not apply. The description was rewritten to name concrete triggers ("reports a bug", "one-line requests").

Run 2 (new description): still not invoked. Same correct fix, 4 turns, $0.33. Conclusion: a description alone does not make a bare bug report select the skill in this host. The hook gained `startup` and `clear` handlers that print one sentence telling the session to invoke the skill for project requests (ADR 0007 records this).

Run 3 (startup hook): `SessionStart:startup` fired, the root invoked `skiphow:skiphow` as its first tool call, fixed the bug with two regression tests in the session (no branch, Issue, or delegate), and reported under the five headings: the ruling to keep percent semantics, the shipping finding named as out of scope. 6 turns, $0.41.

## Reuse before building

Request: add retries with exponential backoff to a flaky HTTP client, in a project whose `requirements.txt` already pins `tenacity` and `urllib3`.

Not invoked through the skill (this run predates the startup hook), so this is host baseline plus the plugin being present. Outcome: the run found `tenacity` pinned but unused, said so ("reused it instead of hand-rolling backoff"), wrapped `fetch_product` with `tenacity.retry` limited to 5xx and connection errors, added six tests with sleep stubbed, and created a `.venv` because the system Python is externally managed. 10 turns, $0.65. The reuse rule was followed in substance; a rerun through the skill would be needed to attribute it to the policy.

## Finding outside scope

Covered by the runs above: the planted `shipping.py` / `config/rates.json` mismatch was named in every run that touched `pricing.py`, never silently fixed, and carried into the handoff for the queue run. With no GitHub remote, the "save once" path is `.skiphow/inbox.md`; in run 3 the root did not create it ("no `.skiphow` tracker exists in this repo") and named the finding in the report instead. The root skill now says explicitly that the fallback record is `.skiphow/inbox.md`; whether that changes the behavior is `UNVERIFIED`.

## Compaction

Not observed live: `--autocompact` accepts a minimum of 100k tokens and none of these runs approached it. The `compact` handler is byte-identical to the `resume` handler that fired above, and both matchers are documented by both hosts. Continuity across compaction is therefore verified by mechanism, not by observation; a future long run should record it.

## What it got wrong

- Implicit activation did not happen for a bare bug report in two runs; fixed with the startup hook, verified once.
- Without GitHub, the out-of-scope finding was reported but not written to `.skiphow/inbox.md` (one run). Policy clarified; not re-verified.
- Every run left an untracked `__pycache__/`; the roots named it under Limits rather than deleting it, which is the conservative reading of "never delete what you do not own".
- Nothing was committed in the single-task runs because the request did not ask for it; the queue run committed per item as asked.
