# 1.6 receipts

Real runs of the 1.6.0 candidate, recorded per [ADR 0008](../../decisions/0008-receipts-over-a-live-harness.md). Same hosts, flags, and orphan fixture as the [1.5 receipts](v1.5-receipts.md). Codex 0.149.1, Claude Code 2.1.246.

## Codex effort per spawn, no role files

Request, identical to the 1.5 Codex receipt: "Review whether shipping rates are consistent across this project without changing anything. Delegate the file inventory to the scout role and the final verdict to the reviewer role, then report." Launched with `codex exec --sandbox workspace-write --json < /dev/null` in a fixture with the skill linked under `.agents/skills/` and no `.codex/agents/`.

Baseline, 1.5 skill: the root spawned `scout` with `fork_turns "3"` and `reasoning_effort "low"`, and `reviewer` with `fork_turns "all"` and `reasoning_effort "high"`. Session logs: scout thread at `low`; reviewer thread shows both `high` and `medium`, consistent with the host's rule that a full-history fork ignores the override. Verdict "inconsistent" with the same file lines as the 1.5 run. Nothing written into the project.

Candidate, routing reference rewritten to spawn with `fork_turns="none"` and the effort per role: both spawns carried `fork_turns "none"`, scout `reasoning_effort "low"`, reviewer `"high"`; the scout thread ran at `low`, the reviewer thread at `high`, root and both delegates on the session model. Same verdict, nothing written into the project. Usage as the host reports it: 350k input tokens (318k cached), 3.2k output.

The role files were redundant before this release; 1.6 removes them and the copy step.

## Portable timestamp

The `Recorded` line now says "UTC time read from the system clock as `YYYY-MM-DDTHH:MM:SSZ`; `unknown` when no clock can be read; never estimated", with no command named. Claude Code, FREESHIP feature on the fixture: the run appended its inbox block through a heredoc with `$(date -u +%Y-%m-%dT%H:%M:%SZ)` and recorded `02:20:20Z` inside the run's `02:19:48Z` to `02:20:29Z` window. 7 turns, $0.54, 7 tests passed. The `unknown` fallback is still unexercised; no run on native Windows.

## What it got wrong

- Both Codex review runs tagged their findings `PERSISTED` in the report and wrote nothing: no `.skiphow/` directory exists in either fixture. The request said "without changing anything", and the tag is not one of `TRACKED`, `SAVED`, `DISMISSED`. On Claude Code the findings rule has held 9 of 10 times; on Codex this is the first read-only request observed, and it did not.
- The Claude Code feature run saved the discount finding with a tag but mentioned the `config/rates.json` mismatch under Limits without one. That is the first untagged finding since the tag became structural (1 of 10).

Both are recorded for dogfooding rather than fixed here; one run each is not enough to choose a wording.

## 1.6.1: read-only requests save nothing

The root skill said saving a finding "is always within authority" while ADR 0004 grants that record only with "fix" or "implement" and makes read-only requests inspection and reporting. 1.6.1 restores ADR 0004: `DELIVER` and `RECORD` grant one record per material finding; a read-only request reports `UNSAVED` ([ADR 0013](../../decisions/0013-read-only-requests-save-nothing.md)).

Codex, same read-only review request as above, 1.6.1 skill, no `.codex/agents/`: report tagged two findings `UNSAVED` and three `DISMISSED` with reasons, "Saved follow-ups: None. The review was read-only.", and no `.skiphow/` directory or other file change. That is the disposition the 1.6 runs lacked.

Claude Code, FREESHIP feature, 1.6.1 skill:

- On `claude-fable-5` (the model of every earlier receipt): both findings `SAVED` as intake blocks, `Recorded: 02:40:43Z` inside the `02:40:02Z` to `02:40:51Z` window, 8 turns, $0.59, 6 passed.
- On `claude-opus-5` (the machine's default at the time): one finding `SAVED`, but as a free-form block without the intake fields or a `Recorded` line, and the rates mismatch not mentioned; 9 turns, $0.34, 6 passed. The run did not read `intake.md`. One run; recorded as a model difference to watch, not changed.
