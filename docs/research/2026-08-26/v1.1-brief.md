# SkipHow 1.1 brief

This is the work order for the next release. It follows from the [system review](system-review.md), the [host research](host-routing-and-continuity.md), the [prior-art mechanics](prior-art-mechanics.md), and [ADR 0007](../../decisions/0007-host-adapters-for-routing-and-continuity.md). Read those four first; do not re-research them.

The implementing agent owns every engineering choice below. The owner has already decided the product direction: one plain-language entry, real model routing without vendor IDs in shared policy, continuity across compaction, shorter policy, fewer docs, and a release the owner can install with one command per host.

Work in this order. Each section lists what to change and what evidence proves it.

## A. Make model routing real

1. Add `plugins/skiphow/agents/scout.md`, `builder.md`, and `reviewer.md` per ADR 0007. Frontmatter: `name`, `description` (so the host can auto-delegate), `model` (`haiku`, `sonnet`, `opus`), `effort` (`low`, omit, `high`), `tools` (scout and reviewer read-only plus Bash for running checks in reviewer; builder gets edit tools and Bash), `isolation: worktree` on builder, `maxTurns` on scout. Bodies of five to ten lines: the role, its boundary, what to return (a short summary, never a transcript), and "policy is in the skiphow skill". No policy copied.
2. Add a Codex section to the routing reference: the optional `[agents]` settings and the three `.codex/agents/*.toml` files the skill may write on request. Never write them unasked.
3. Rewrite `references/model-routing.md` to about 250 words: the three roles, when to delegate at all (isolation or parallelism, otherwise stay in context), "name the role, never inherit by omission", turn count beats token price, escalate one tier after a second same-cause failure, stop after one more, report the effective route when the host substitutes. Remove the "map only from host metadata" rule.
4. Update ADR 0003: mark the metadata-only mapping rule as superseded by ADR 0007 and leave the rest.
5. `scripts/check.py`: allow `agents/` and `hooks/` as plugin top-level entries; require exactly the three agent files; scan them for versioned model IDs (extend the regex so bare aliases pass and anything with a version number or dated suffix fails); require each agent's `model` to be one of `haiku`, `sonnet`, `opus`, `inherit`.
6. Evidence: `python scripts/check.py`, `python scripts/check_hosts.py` on both hosts, and one real Claude Code session in a throwaway repository where a `scout` delegation reports a different model from the root. Record the effective models in the PR. If Codex can also be checked with the optional settings, record it; otherwise `UNVERIFIED`.

## B. Continuity across compaction and restart

1. Add `plugins/skiphow/hooks/hooks.json` for Claude Code and the equivalent Codex plugin hook declaration, each with one `SessionStart` hook matching `compact` and `resume`. Command: a POSIX `sh -c` one-liner that prints "SkipHow: a session resumed or compacted. Re-read the owner request, then Git and GitHub state. If .skiphow/handoff.md exists, its latest checkpoint follows." and, when the file exists, `tail -n 40 .skiphow/handoff.md`. No other events, no network, no writes.
2. Change `references/long-work.md` and the root skill so the handoff is written at every item boundary and before a long wait, not "before compaction".
3. Shrink the checkpoint to eight lines: Recorded, Outcome, Selected scope, Authority and restrictions, Done, In progress with exact Git and GitHub identity, Blockers, Next safe action. Drop the exact-label list from the test.
4. Amend AGENTS.md, ADR 0002 and ADR 0006 (one sentence each), `scripts/check.py`, and `tests/test_repository.py`: hooks are limited to the continuity hook, verified by content.
5. Evidence: a Claude Code session with `--autocompact` set low enough to force compaction mid-task, after which the resumed session reads the handoff and continues without repeating finished work. Record the transcript summary in the PR. Codex the same or `UNVERIFIED`.

## C. Cut the policy to intent plus invariants

Target sizes: root skill under 600 words, all references together under 2,800 words, no single reference over 600. Write for a strong model: what to achieve, the few things that must never happen, and when to load more. Delete procedure that a capable model derives on its own.

1. `SKILL.md`: keep authority, four routes, "smallest sufficient path", reuse before building (one sentence), findings rule (one sentence), completion rule (compare final state with request, fresh checks, report rulings and limits). Add the daily flow as the mental model: discuss, save, then finish end to end.
2. `references/long-work.md` (1,141 words) to about 500: selected queue is fixed; dependencies decide readiness; one root integrates; delegates get a brief file and return a summary; four reasons to stop (irreversible action, security-sensitive action, external side effect beyond the grant, plan so broken every path is a guess), otherwise record a ruling and continue; cap same-cause retries at two then stop; handoff at boundaries; at the end every selected item is done, blocked with a next action, or deferred by the owner.
3. `references/github.md` (770 words) to about 450: Issue is the record, PR is the delivery, branch and worktree owned by the run; before merge re-read live state (head, checks, reviews, rules); merge only with end-to-end authority and never with bypass; after merge close the Issue, delete only the branch this run created and GitHub reports merged from the recorded head, prune the worktree; never delete unmerged or foreign work. Remove marker mechanics beyond "put a stable `skiphow:<id>` marker in bodies you create and search for it before creating again". Add "finish today's batch": a `RECORD` run labels or marks the Issues it created with a batch marker so the owner can say "finish the batch from today end to end" without listing numbers.
4. `references/delivery.md` (678 words) to about 400. Strengthen reuse: before writing a new module or feature, search the project, its dependencies, and the platform by domain concept; state in the report where you looked and what you reused. Findings become one paragraph: fix if it blocks, save once if material, list under "Rulings and findings" in the report. Keep the dirty-file baseline rule as one sentence.
5. `references/intake.md`: keep dispositions but shorten to about 250 words. Keep the inbox block format.
6. `references/decision.md`, `diagnosis.md`, `engineering.md`, and `methods/*`: shorten by roughly a third each, keep the seams that tests reference only if they describe behavior.
7. Completion report format, in the root skill, five headings: Result, Evidence, Rulings and findings, Saved follow-ups, Limits. Superpowers' "rulings I made" is the model.
8. Evidence: `scripts/context_budget.py` extended with a references budget; both budgets in `context_budget_baseline.json`; check passes.

## D. Tests check structure, not sentences

1. Replace every `assert "<sentence>" in <file>` in `tests/test_repository.py` with structural checks: routes present, references linked and complete, agents and hook present with allowed fields and values, no versioned model IDs, no personal paths, manifests aligned, budgets met, inbox and handoff formats present as fenced blocks, report headings present.
2. Keep `test_release_checks.py`, `test_context_budget.py`, and the live-eval schema tests that do not assert prose.
3. Evidence: `python scripts/check.py`.

## E. One owner guide, one README, no duplicate docs

1. Delete `docs/intake.md`, `docs/github-lifecycle.md`, `docs/model-routing.md`, `docs/user-guide.md`, and `docs/threat-model.md`. Fold anything not in the references into two files: `docs/guide.md` (owner-facing: the daily flow, what words authorize, unattended launch recipes for both hosts, pause and resume, what the report means, where records live, uninstall) and `docs/how-it-works.md` (architecture, routing, GitHub lifecycle, trust and limits, in about 1,200 words). Keep `docs/evals.md` but cut it to the commands and the claims policy. Keep `docs/prior-art.md`. Keep `docs/decisions/` and `docs/research/`.
2. `docs/README.md` becomes a six-line index.
3. Unattended launch recipes, verified against `--help` of the installed hosts before writing: Claude Code `claude -p "<request>" --permission-mode auto --max-budget-usd <n>`; Codex `codex exec --sandbox workspace-write --approve-for-me "<request>"` or the current equivalent. Say what each flag does in one line and that host permissions still apply.
4. Fix every link in README, CONTRIBUTING, SECURITY, and the ADRs after the moves. `scripts/check.py` catches broken links.

## F. Repository hygiene and release

1. Remove untracked leftovers from the runner era: `build/`, empty `src/`, empty `.worktrees/`, `evals/deterministic/`, `evals/graders/`. Drop `.skiphow/runs/` and `.skiphow/intake/` from `.gitignore`; add `.skiphow/handoff.md` only if the owner wants it ignored (default: committed, it is a project record).
2. Add `.github/workflows/release.yml` triggered by a `v*` tag: run `scripts/check.py` and the Codex validator, then create the GitHub release with the matching CHANGELOG section as the body. SHA-pin actions. Document in CONTRIBUTING that a release is "bump VERSION, update CHANGELOG, tag".
3. Update `SECURITY.md` supported versions to `1.1.x`.
4. Bump `VERSION` and both manifests to `1.1.0`. CHANGELOG entry: routing adapters, continuity hook, shorter policy, docs consolidation, structural tests, release workflow, and the verification status.
5. Evidence: `python scripts/check.py`, `python scripts/check_hosts.py`, `git diff --check`, CI green, `claude plugin update` and `codex plugin add` from the tagged release on this machine.

## G. First real receipt

After 1.1 is tagged, run the owner's daily flow once on a real project of the owner's choosing: dump five to ten bugs and ideas, ask SkipHow to triage and save them as Issues, then ask it to finish the batch end to end with a budget. Record in `docs/research/<date>/dogfood-receipt.md`: what was asked, which Issues were created, which PRs merged, which delegations used which effective model, tokens and cost from the host, what was cleaned up, what it got wrong. This receipt is worth more than the live harness. Only after it exists decide whether `evals/live` should be kept, cut to three scenarios, or removed.

## Out of scope for 1.1

- Any SkipHow runner, daemon, database, or provider bridge (ADR 0002).
- Additional hooks beyond the continuity hook (ADR 0007).
- Versioned model IDs anywhere in the package.
- New public commands (ADR 0001).
- Claims of cost savings before paired runs exist.

## Done means

Every item above is implemented or listed in the PR as `BLOCKED` with the reason. All checks pass on the final commit. Both hosts install the tagged release. ADR 0007 status is changed to Accepted in the same PR.
