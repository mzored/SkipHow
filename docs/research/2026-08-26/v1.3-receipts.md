## Codex: small task

Request: "Customers who get a 10 percent discount see a negative order total. Find the cause and fix it."

First action: read `SKILL.md`, then `delivery.md`, `diagnosis.md`, and `engineering.md`. It wrote a regression test first and ran it (a $20 order at 10 percent returned `-180.0`), fixed `apply_discount`, ran the suite (4 passed) and `git diff --check`, and reported under the five headings with one ruling (the conversion belongs in `apply_discount`). No branch, Issue, commit, or delegate. It did not open `shipping.py`, so it did not meet the planted finding and reported "Saved follow-ups: None", which is accurate for what it read. 212k input tokens (174k cached), 2.3k output.

## Codex: brain dump to inbox

Request: four notes (the negative total, the 5.0 versus 6.0 shipping question, a FREESHIP idea, "someday: dark mode for the admin panel") and "Triage these and save them." No GitHub remote.

It named the route (`RECORD`), reproduced the discount bug and the rate mismatch on the current branch, then found in the local `main` history that the discount fix and the coupon were already merged as #8 and #11, and read those commits before calling them duplicates. It wrote four blocks to `.skiphow/inbox.md` in the intake format with a `Priority` line each (P0 duplicate, P1 `NEEDS_RESEARCH`, P2 duplicate, P3 `NEW` for dark mode, noting no admin panel exists), changed no product code, and reported counts, order, and the GitHub limit under the five headings. 221k input tokens (167k cached), 4.2k output.

Both Codex runs also loaded the owner's personal `unslop` skill from the user skills directory; that is the machine, not the plugin.

## Claude Code: continuity across an observed compaction

Request, through `-p --input-format stream-json` with a driver that waits for each event: a three-item queue "commit each one on this branch", with "do item 1 only now, commit it, write your handoff checkpoint, and stop"; then `/compact`; then, after the `compact_boundary` event, "Continue the queue to the end."

Session part 1: `SessionStart:startup` fired from the new `startup|clear` group; the root's first tool call was `Skill(skiphow:skiphow)`; it fixed item 1 with a test that fails on the old code, committed, wrote the eight-line checkpoint, and stopped. 8 turns, $0.55.

Compaction: `compact_boundary` (manual, 24,127 tokens before, 3,923 after). `SessionStart:compact` fired from the `compact|resume` group and its output was the reminder sentence followed by the checkpoint.

Part 2: the first tool call was `git status && git log`; item 1 was not touched; items 2 and 3 were implemented with tests and committed (10 passed); the report listed the rulings (optional `coupon` keyword, unknown method checked before the coupon) and named the shipping-rate mismatch as out of scope. 4 turns, $1.11 cumulative.

Continuity across compaction is verified on Claude Code, with the two-group hook. A first attempt of the same run, whose driver closed stdin early, reached the same three commits.

## Claude Code: a large request end to end on GitHub

Request, in a fresh clone of the throwaway repository: "Add a loyalty points program: customers earn one point per whole dollar of an order's final total, 100 points can be redeemed for a 1.00 discount on a later order, and an order records the points it earned. Finish this end to end. Merge what passes."

The root searched `labshop/` and the dependencies for an order, customer, or account concept (none), searched open and closed Issues and pull requests for "loyalty", created Issue #12 with a marker, branched `skiphow/12-loyalty-points`, added `loyalty.py` with 19 tests and a README section, opened PR #13, re-read mergeability and the head SHA, merged with `--match-head-commit`, confirmed the merge from GitHub, deleted the branch, and reported (34 passed on merged `main`). Rulings: points accrue on the total after redemption; redemption must be a multiple of 100 within the balance; shipping is outside `order_total` so it earns nothing. 14 turns, 121 s, $1.19.

It judged the request bounded enough for one Issue and one delegate-sized change, and did not decompose it or delegate. That is within the policy ("an epic ... that each fit one delegate"); the decomposition path for a request that does not fit one delegate has no receipt yet.

## What it got wrong

- Neither continuity run deleted `.skiphow/handoff.md` when the queue was done; both appended a "queue finished" checkpoint instead. The 1.2 resume run did delete it. The rule lives in `long-work.md`, which a compacted session may not re-read, so 1.3 adds nine words to the compaction hook line ("delete that file once every selected item is done"). Whether that changes the behavior is `UNVERIFIED`.
- The continuity run named the shipping-rate mismatch and did not save it to the inbox ("left alone as out of scope"). The Codex intake run and every 1.2 delivery run did save it. The judgment "when material" differs between runs.
- Fixture clones carried a `main` branch with later fixes; the Codex intake run used it as tracker history. Harmless here, but a cleaner fixture would be an orphan checkout.
