# 1.5 receipts

Real runs of the 1.5.0 candidate, recorded per [ADR 0008](../../decisions/0008-receipts-over-a-live-harness.md). Same hosts, flags, and orphan fixture as the [1.4 receipts](v1.4-receipts.md). The paired experiment behind the `DELIVER` change is in [paired-eval.md](paired-eval.md).

## Timestamps

The 1.4 receipts noted an inbox block recorded at `00:00:00Z`. The intake and handoff templates said `<RFC 3339 UTC timestamp>` and the model filled in the shape. They now say the value is the output of `date -u +%Y-%m-%dT%H:%M:%SZ`, or `unknown` when no clock is available.

Receipt: a three-note brain dump with no tracker, wrapped in `date -u` calls. Window `02:00:28Z` to `02:01:09Z`; all three blocks recorded `02:00:40Z`. The two feature runs below recorded `02:03:08Z` and `02:03:11Z` during their own windows. No `unknown` fallback has been exercised; both hosts have a shell.

## Bounded delivery without the delivery reference

After the paired experiment, the root skill says a clear bounded change needs no reference. Two FREESHIP feature runs on the final wording: 6 passed each, two findings each `SAVED` as intake blocks with dispositions (`NEW`, `NEEDS_RESEARCH`) after reading `intake.md`, 7 and 8 turns, $0.54 and $0.61. The findings invariant now stands at 8 of 8 findings saved across the six feature runs since the tag was introduced.

## Codex scout and reviewer

Request in a fixture with the three role files in `.codex/agents/`: "Review whether shipping rates are consistent across this project without changing anything. Delegate the file inventory to the scout role and the final verdict to the reviewer role, then report." Launched with `codex exec --sandbox workspace-write --json < /dev/null`.

The root read the routing reference, spawned `scout` for the inventory and `reviewer` for the verdict (two `wait` collaboration calls), changed nothing, and reported "inconsistent" with the file lines, the untested standard rate, and the unread config. Session logs: scout thread `agent_role: scout`, effort `low`; reviewer thread `agent_role: reviewer`, effort `high`; root and both delegates on `gpt-5.6-sol`. Together with the 1.4 builder run, all three role files are now observed: role, sandbox, and effort per role on the session model. No model routing exists on Codex to observe.

## What it got wrong

- The first Codex run of this pass blocked on stdin for minutes when launched from a background shell; `codex exec` reads additional input from stdin, so unattended launches need `< /dev/null`. The guide's example is unaffected in a terminal.
- One variant run wrote both findings into one loosely formatted inbox block before the "after reading intake" wording; see the paired evaluation.
