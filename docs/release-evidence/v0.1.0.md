## Local marketplace checks and limitations

In a temporary local clone, this command completed:

```sh
claude plugin marketplace add --scope local ./
```

Output: `Successfully added marketplace: skiphow (declared in local settings)`.

`claude plugin list --available --json` then reported one available entry:

```json
{
  "pluginId": "skiphow@skiphow",
  "name": "skiphow",
  "marketplaceName": "skiphow",
  "version": "0.1.0",
  "source": {"source": "github", "repo": "mzored/SkipHow"}
}
```

An exact-candidate marketplace installation was not run. The marketplace entry deliberately points at the public GitHub repository without a branch ref, so installation before merge would fetch the default branch rather than this candidate. Codex CLI also has no documented profile-directory option. Its plugin marketplace commands write the active Codex profile, and its `-c` option only overrides configuration values. The machine policy for this verification forbids reassigning `HOME` or `CODEX_HOME`, so no clean isolated Codex installation was attempted. The same policy prevented use of a temporary home for Claude Code. These are limitations, not successful installation claims.

The temporary virtual environment and local profile were moved to Trash after the checks. The execution guard rejected recursive deletion, so they remain recoverable.
